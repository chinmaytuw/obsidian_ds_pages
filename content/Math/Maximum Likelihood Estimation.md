# 1. MLE - Motivation
- MLE is an <mark style="background: #FF5582A6;">objective function</mark>. (<mark style="background: #FF5582A6;">Not an optimizer</mark>)
- Question is why do we need it? The core problem it tries to solve:  
    >You have **data** (observations from the real world) and a **model** with unknown parameters. You need to figure out what those parameters should be.
- <mark style="background: #ADCCFFA6;">MLE defines WHAT needs to be done. It doesn't talk about HOW it needs to be done</mark>.


## 1.2 MLE in linear regression
- Although we can use it, we don't necessarily need MLE for linear regression.
- Think #regression. For linear regression, we can estimate coefficients by minimizing **Residual Sum of Squares (RSS)** — a deterministic approach that even has a closed form solution:
$$\hat{\beta} = (X^TX)^{-1}X^Ty$$
- MLE is a **probabilistic alternative** that asks a different question: *"Find the parameters that make the observed data most likely."*
- The key philosophical flip MLE makes: **treat data as fixed, parameters as the variable** — the opposite of how you usually think about probability.
$$L(\theta) = P(\text{data} \mid \theta)$$
- <mark style="background: #FFF3A3A6;">For linear regression specifically, MLE and RSS arrive at the same answer. This is because RSS implicitly assumes Gaussian errors</mark>:
$$y_i = \beta_0 + \beta_1 x_i + \varepsilon_i, \quad \varepsilon_i \sim N(0, \sigma^2)$$
- Under this assumption, the log-likelihood simplifies to:
$$L(\theta) = \prod_{i} P(y_i \mid x_i, \theta)$$
$$\ell(\theta) = \sum_{i} \log P(y_i \mid x_i, \theta)$$
$$\ell(\theta) \propto -\sum_{i}(y_i - (\beta_0 + \beta_1 x_i))^2$$

- Which is exactly RSS. So their equivalence isn't a coincidence — it falls directly out of the Gaussian assumption.
> **Note:** Linear regression is used here as a familiar bridge to understand MLE. It is not a good *motivating* case for MLE since you don't need it there — a closed form solution already exists.

#### 1.3.2 So Why Do People Still Use Gradient Descent on Linear Regression?
- Because the closed-form solution has a dirty secret — it requires **inverting a matrix**, and that becomes brutally expensive at scale.
- Matrix inversion is $O(n^3)$ in the number of features. So if you have:
	- 1,000 features → fine
	- 100,000 features → painful
	- Millions of features (think embeddings) → practically impossible


## 1.3 Why MLE? — The Real Motivation
- The <mark style="background: #ADCCFFA6;">Gaussian assumption breaks down the moment your output variable has a different natural distribution</mark>. This is called a **non-Gaussian setting**:

| Output Type | Natural Distribution | Example |
|-------------|---------------------|---------|
| Binary (0/1) | Bernoulli | Will a player churn? |
| Probability | Binomial | Click-through rate |
| Counts | Poisson | Matches played per week |
| Skewed continuous | Gamma / Log-normal | Player spend, session length |

- In these settings, RSS is the **wrong objective** — a Gaussian can produce negative values, decimals where you need integers, etc.
- MLE's recipe stays the same regardless of distribution. **You just swap in the appropriate likelihood:**

| Setting | Likelihood | Resulting Objective |
|---------|-----------|-------------------|
| Gaussian errors | Gaussian | RSS |
| Binary output | Bernoulli | Cross-entropy loss |
| Count output | Poisson | Poisson log-likelihood |

- This is where MLE earns its keep. The **true motivating case** is logistic regression:
	  - Binary outcomes (0/1), so Gaussian assumption makes no sense
	  - No closed form solution exists
	  - MLE is the only principled path: assume $y_i \sim \text{Bernoulli}(p_i)$, write the likelihood, maximize it
- MLE is also the foundation for neural nets, Gaussian mixture models, HMMs, VAEs — anywhere you can write down a likelihood and no closed form exists.

## 1.4 Various ways to do MLE
- There are 2 main ways of solving for MLE: 
	- analytical where you reduce to a system of equations and then solve for it. This works fine for simple problems like linear regression.
	- For more complex system, we use [[gradient descent]]


## 1.5 MLE vs RSS
- Both MLE and RSS are objective functions. Meaning, WHAT needs to be achieved. 
	- - **RSS** — starts from a <mark style="background: #ADCCFFA6;">geometric</mark>/intuitive place — "my predictions should be close to the actual values, so let me minimize the squared distances between them." There's no probability in that framing at all. <mark style="background: #FFB86CA6;">The goal is to minimize errors</mark>. We solve it via OLS, which is a *solver*. 
	- **MLE** — starts from a probabilistic place — "my data was generated by some distribution with unknown parameters, so <mark style="background: #FFB86CA6;"> my goal is to find the parameters that make this particular dataset most probable</mark>". 

> [!Note]
> - RSS and MLE objective functions. 
> - OLS is RSS's solver. Gradient Descent (among others) is MLE's solver.

## Further Details:
---
- Maximum Likelihood Estimation is a fundamental statistical method for estimating the parameters of a probabilistic model.
- The core principle is straightforward: given observed data, find the parameter values that make that data most probable under your assumed model. Mathematically, if your data is X = {x₁, x₂, ..., xₙ} and your model has parameters θ, you maximize the likelihood function L(θ) = P(X | θ). #likelihood
- In practice, we work with the log-likelihood ( #log_likelihood) because it's computationally easier—it transforms products into sums and is numerically more stable. Since the logarithm ( #log) is monotonically increasing, maximizing log L(θ) is equivalent to maximizing L(θ).
- The optimization is typically done by taking the derivative of the log-likelihood with respect to the parameters, setting it to zero, and solving. For complex models where analytical solutions don't exist, we use numerical optimization methods like gradient descent.
- MLE is deeply connected to the #loss_function s commonly used in machine learning. Minimizing mean squared error in linear regression is equivalent to MLE under the assumption of Gaussian noise. Minimizing #cross_entropy loss in classification is equivalent to MLE for #Bernoulli or categorical distributions. When you train a neural network with gradient descent on cross-entropy loss, you're performing MLE. This makes MLE not just a theoretical concept but the mathematical foundation underlying most supervised learning algorithms. The framework provides consistency (estimates converge to true values with enough data), efficiency (achieves low variance), and a principled way to estimate parameters for any parametric model.

## **Properties of MLE**
- **Consistency**: As the sample size increases, MLE converges in probability to the true parameter value.
- **Asymptotic Normality**: For large sample sizes, the distribution of MLE estimates approaches a #normal_distribution.
- **Efficiency**: MLE achieves the lowest possible variance among unbiased estimators under certain conditions.
## **Limitations**:
- MLE can be sensitive to outliers and may not perform well with small sample sizes.
- It requires a correct specification of the model; if the model is mis specified, MLE may yield biased estimates.

# For Linear Regression

### Setup

Suppose we have 4 data points relating study hours (x) to test scores (y):

| Study Hours (x) | Test Score (y) |
| --------------- | -------------- |
| 1               | 3              |
| 2               | 5              |
| 3               | 7              |
| 4               | 9              |

We want to fit a linear model: **y = β₀ + β₁x + ε**, where ε ~ N(0, σ²)
For simplicity, assume σ² = 1 (known variance).

### Step 1: Write the Likelihood Function

For each data point, the probability density is:
	$P(yᵢ | xᵢ, β₀, β₁) = (1/√(2πσ²)) exp(-(yᵢ - (β₀ + β₁xᵢ))² / (2σ²))$

Since observations are independent, the likelihood is the product:
	$L(β₀, β₁) = ∏ᵢ₌₁⁴ P(yᵢ | xᵢ, β₀, β₁)$

---

### Step 2: Take the Log-Likelihood

**log L(β₀, β₁) = Σᵢ₌₁⁴ log P(yᵢ | xᵢ, β₀, β₁)**
**= Σᵢ₌₁⁴ [log(1/√(2π)) - (yᵢ - (β₀ + β₁xᵢ))² / 2]**

Dropping constants (they don't affect the argmax):
**log L(β₀, β₁) ∝ -½ Σᵢ₌₁⁴ (yᵢ - β₀ - β₁xᵢ)²**

Maximizing this is equivalent to **minimizing the residual sum of squares (RSS)**:
**RSS = Σᵢ₌₁⁴ (yᵢ - β₀ - β₁xᵢ)²**

---

### Step 3: Take Partial Derivatives

**∂(RSS)/∂β₀ = -2 Σᵢ₌₁⁴ (yᵢ - β₀ - β₁xᵢ)**

**∂(RSS)/∂β₁ = -2 Σᵢ₌₁⁴ xᵢ(yᵢ - β₀ - β₁xᵢ)**

---

### Step 4: Set Derivatives to Zero

From ∂(RSS)/∂β₀ = 0:

**Σ(yᵢ - β₀ - β₁xᵢ) = 0**

**Σyᵢ - nβ₀ - β₁Σxᵢ = 0**

**4β₀ + β₁(10) = 24** ... (Equation 1)

From ∂(RSS)/∂β₁ = 0:

**Σxᵢ(yᵢ - β₀ - β₁xᵢ) = 0**

**Σxᵢyᵢ - β₀Σxᵢ - β₁Σxᵢ² = 0**

**10β₀ + β₁(30) = 70** ... (Equation 2)

---

### Step 5: Solve the System

From our data: (<mark style="background: #D2B3FFA6;">This is where the data gets plugged in</mark>)

- n = 4
- Σxᵢ = 1 + 2 + 3 + 4 = 10
- Σyᵢ = 3 + 5 + 7 + 9 = 24
- Σxᵢ² = 1 + 4 + 9 + 16 = 30
- Σxᵢyᵢ = 3 + 10 + 21 + 36 = 70

From Equation 1: **β₀ = (24 - 10β₁) / 4 = 6 - 2.5β₁**

Substitute into Equation 2:

**10(6 - 2.5β₁) + 30β₁ = 70**

**60 - 25β₁ + 30β₁ = 70**

**5β₁ = 10**

**β₁ = 2**

Therefore: **β₀ = 6 - 2.5(2) = 1**

---

### Final Result

**ŷ = 1 + 2x**

This perfectly fits our data! The MLE estimates are β₀ = 1 and β₁ = 2, which minimize the sum of squared residuals.
